## 0. Ключевые инсайты SEO 2026

**Яндекс vs Google — принципиальная разница:**
- Яндекс: поведенческие факторы ~45% формулы ранжирования (CTR, время на сайте, возвраты), ссылки ~30%
- Google: ссылки и E-E-A-T весят больше, Core Web Vitals критичны
- Оба используют нейросети для семантического анализа (Яндекс: "Королёв", "YaTI")

**AEO (Answer Engine Optimization) — новая реальность:**
- ~60% поисковых запросов Google заканчиваются без клика (AI Overviews)
- ~35% запросов Яндекса отвечаются без клика (ЯндексGPT)
- **Правило 50 слов**: в начале каждой секции — лаконичный ответ 40-60 слов (LLM извлекают как цитаты)
- Модульный контент с чёткими H2/H3 — LLM "чанкают" по заголовкам

**INP (Interaction to Next Paint) — новый CWV:**
- Заменил FID, 43% сайтов не проходят порог (200ms)
- Критично для Next.js: тяжёлая гидрация, анимации, клиентские компоненты

**Топиковые кластеры:**
- Кластерная модель даёт ~30% больше органического трафика vs изолированные статьи
- Pillar-страница (3000-10000 слов) → 5-20 supporting-страниц → перекрёстная перелинковка

## 3. Техническое SEO (Wave 1)

### 3.1 Рендеринг и скорость (P0)

**Проблема:** `force-dynamic` в layout.tsx отключает все оптимизации Next.js.

**Решение:** Убрать `force-dynamic`, настроить ISR с revalidate: 60 на каждой странице.

```
layout.tsx: удалить export const dynamic = "force-dynamic"
Каждая page.tsx: export const revalidate = 60
```

**Ожидаемый эффект:** TTFB с ~500-800ms → ~50-100ms для повторных запросов.

### 3.2 Google Search Console + Яндекс Вебмастер (P0)

1. Зарегистрировать stackovervibe.ru в GSC
2. Верификация через DNS TXT-запись или HTML-файл
3. Отправить sitemap.xml
4. Зарегистрировать в Яндекс Вебмастер
5. Верификация
6. Отправить sitemap.xml
7. Настроить региональность (Россия) в Вебмастере

### 3.3 robots.txt (P2)

### 3.4 Sitemap (P2)

Изменения:
- Убрать /search из sitemap (он теперь в Disallow)
- Добавить /privacy
- Добавить /about (после создания)
- Тег-страницы: включать только теги с >3 материалами (остальные — noindex)

### 3.5 Canonical URL (P2)

- Добавить canonical на ВСЕ страницы (включая листинги)
- Пагинация: canonical на первую страницу (или self-referencing)
- /search: noindex, nofollow (параметрические страницы)

### 3.6 Мета-теги для тонких страниц (P1)

Тег-страницы с <3 материалами:
```html
<meta name="robots" content="noindex, follow">
```
Это позволяет поисковику переходить по ссылкам, но не индексировать саму страницу.

### 3.7 Preload критических ресурсов (P2)

В layout.tsx добавить в <head>:
```html
<link rel="preload" href="/fonts/space-mono-latin.woff2" as="font" type="font/woff2" crossorigin>
<link rel="preload" href="/fonts/inter-cyrillic.woff2" as="font" type="font/woff2" crossorigin>
```

### 3.8 Оптимизация изображений (P2)

В next.config.ts:
```typescript
images: {
  formats: ["image/avif", "image/webp"],
  deviceSizes: [640, 750, 828, 1080, 1200],
}
```

### 3.9 HTTP-заголовки (P2)

В next.config.ts добавить security + cache headers:
```typescript
headers: async () => [
  {
    source: '/:path*',
    headers: [
      { key: 'X-Content-Type-Options', value: 'nosniff' },
      { key: 'X-Frame-Options', value: 'DENY' },
    ],
  },
  {
    source: '/fonts/:path*',
    headers: [
      { key: 'Cache-Control', value: 'public, max-age=31536000, immutable' },
    ],
  },
]
```

## 4. On-page SEO (Wave 2)

### 4.1 Внутренняя перелинковка (P0)

**Стратегия: Hub & Spoke**

Хаб-страницы (существующие листинги) должны ссылаться на все детальные, а детальные — ссылаться друг на друга по контексту.

**Автоматическая перелинковка:**
Создать компонент `RelatedLinks`, который:
1. На каждой странице инструмента показывает "Связанные гайды" и "Похожие вопросы"
2. На каждом гайде показывает "Инструменты из этого гайда" и "Вопросы по теме"
3. На каждом вопросе показывает "Полезные инструменты" и "Гайды по теме"

Связи определять по общим тегам.

**Контекстные ссылки в теле:**
При создании нового контента — обязательно 3-5 внутренних ссылок на другие страницы сайта. Добавить в правила для AI-создания контента.

### 4.2 Дата публикации и обновления (P2)

На каждой детальной странице показывать:
- "Опубликовано: DD.MM.YYYY"
- "Обновлено: DD.MM.YYYY" (если отличается)

В JSON-LD: datePublished + dateModified.

### 4.3 Оптимизация заголовков (P1)

Каждая страница должна иметь:
- **Один H1** — уникальный, содержит ключевое слово
- **H2** — подразделы контента
- **H3** — вложенные подразделы

Проверить и исправить:
- Homepage: убрать дублирующий sr-only H1
- Листинги: card titles обернуть в H2/H3

### 4.4 Meta descriptions (P1)

Требования:
- 140-160 символов
- Содержит ключевое слово
- Содержит CTA или value proposition
- Уникальная для каждой страницы

Для страниц без seoDescription — генерировать автоматически из excerpt/shortDescription с обрезкой до 160 символов.

### 4.5 Title теги (P1)

Формат: `{Ключевое слово} — {Уточнение} | Stackovervibe`

Примеры:
- "Что такое вайбкодинг — Полный гайд для начинающих | Stackovervibe"
- "Claude Code настройка — Пошаговая инструкция | Stackovervibe"
- "Cursor vs Claude Code — Сравнение AI-редакторов | Stackovervibe"

Текущий формат `%s — Stackovervibe` — допустим, но title страниц нужно оптимизировать.

### 4.6 Open Graph изображения (P1)

**Этап 1:** Заменить og-default.png на реальное брендированное изображение 1200x630.

**Этап 2:** Динамическая генерация OG для каждой страницы:
- Использовать @vercel/og или next/og
- Шаблон: тёмный фон + название страницы + тип контента + лого
- Ретро-хакерский стиль (консистентность с дизайном)

### 4.7 Страница "Об авторе" и E-E-A-T (P1)

Создать /about с:
- Имя автора, фото (опционально)
- Описание опыта в разработке и AI
- Ссылки: Telegram, GitHub
- Упоминание проектов (grambotica, zachot, vibe-framework)
- schema.org Person

На каждой странице контента показывать автора со ссылкой на /about или /profile/[username].

### 4.8 Расширенные профили пользователей (P2)

Добавить в Users коллекцию:
- bio (текстовое описание)
- website (URL)
- github (username)
- expertise (теги экспертизы)

На /profile/[username] — отображать и добавить schema.org Person.

### 6.2 Формат контента

Каждая статья должна содержать:
1. **H1 с ключевым словом** (в первых 60 символах title)
2. **Блок-ответ 40-60 слов** — первый абзац прямо отвечает на запрос (для featured snippet + LLM-цитирования)
3. **Содержание** (Table of Contents) для длинных статей
4. **Модульные секции с H2/H3** — каждая секция самодостаточна (LLM чанкуют по заголовкам)
5. **3-5 внутренних ссылок** на другие страницы сайта (описательный anchor text, не "нажмите здесь")
6. **Практические примеры** (код, команды, скриншоты) — маркер E-E-A-T Experience
7. **FAQ-секция** внизу (для People Also Ask + ЯндексGPT)
8. **CTA** (скачать .md, пройти путь, задать вопрос)
9. **Минимум 1500 слов** для хаб-страниц, 800+ для обычных
10. **Таблицы и списки** — предпочтительный формат для LLM-парсинга

### 6.3 Частота публикаций

**Рекомендация: 2-3 статьи в неделю первые 2 месяца, потом 1-2 в неделю.**

Это агрессивный темп, но необходимый для быстрого набора индексируемых страниц. Часть контента можно генерировать с помощью AI и редактировать вручную.

### 6.4 Обновление существующего контента

Раз в месяц:
- Проверять актуальность всех гайдов и инструментов
- Обновлять dateModified
- Добавлять новые ссылки на свежий контент
- Расширять статьи свежими примерами

## 8. LLM-видимость / AEO (Wave 5, второй этап)

### 8.1 Подготовка к индексации LLM

LLM-поисковики (Perplexity, ChatGPT Browse, Claude) предпочитают:
- Чёткие, структурированные ответы в начале статьи
- Списки и таблицы (легко парсить)
- Авторитетные источники с E-E-A-T
- Уникальный контент, которого нет на Wikipedia/Habr

### 8.2 Действия

1. **Формат "Ответ сразу"**: Каждая статья начинается с 2-3 предложений, прямо отвечающих на запрос
2. **Структурированные списки**: Топ-N, чеклисты, пошаговые инструкции
3. **llms.txt**: Создать файл /llms.txt (аналог robots.txt для LLM) с описанием сайта и ключевого контента
4. **Schema.org максимум**: Чем больше структурированных данных, тем лучше LLM понимают контент
5. **Уникальность**: Фокус на контенте, которого нет у конкурентов (конкретные конфиги, рабочие промпты, реальные кейсы)

### 8.3 Мониторинг

- Проверять упоминания stackovervibe в ответах ChatGPT, Claude, Perplexity
- Отслеживать реферальный трафик из AI-сервисов в аналитике

## 9. Подготовка к мультиязычности (Wave 5)

### 9.1 Архитектурные решения сейчас

Чтобы не переделывать потом:
1. **URL-структура**: Заложить возможность /en/ префикса (subpath routing)
2. **Контент в CMS**: Не хардкодить русский текст в компонентах — выносить в CMS или i18n-файлы
3. **hreflang**: Пока не нужен, но код metadata-генератора должен поддерживать добавление
4. **next-intl или аналог**: Не устанавливать сейчас, но не создавать архитектурных блокеров

### 9.2 Когда переходить

Триггер: когда русскоязычный трафик стабилизируется на 5000+/мес и появится ресурс на перевод/создание EN-контента.

## 11. Риски и митигация

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Медленная индексация новых страниц | Средняя | Отправка URL через GSC, ссылки с внешних ресурсов |
| Конкуренция с медиа-гигантами (Habr, Skillbox) | Высокая | Фокус на длинный хвост и экспертные запросы |
| Duplicate content (GitHub vs сайт) | Средняя | Canonical на сайт, переработка текстов |
| Потеря позиций из-за обновлений алгоритма | Низкая | White-hat подход, качественный контент |
| Не хватит ресурса на 2-3 статьи/неделю | Средняя | AI-assisted создание контента, шаблоны |

## 12. Чеклист для каждой новой публикации

- [ ] Title содержит ключевое слово (до 60 символов)
- [ ] Meta description 140-160 символов с CTA
- [ ] H1 уникальный, содержит ключевое слово
- [ ] Вводный абзац отвечает на запрос (для featured snippet)
- [ ] 3-5 внутренних ссылок на другие страницы
- [ ] Минимум 800 слов (1500+ для хаб-страниц)
- [ ] Изображения с alt-текстом (когда появятся)
- [ ] JSON-LD структурированные данные
- [ ] Canonical URL
- [ ] OG-изображение
- [ ] Дата публикации видна
- [ ] FAQ-секция (если применимо)
- [ ] CTA в конце (скачать, пройти путь, задать вопрос)
